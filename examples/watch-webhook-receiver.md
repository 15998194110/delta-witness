# Watch webhook receiver contract

`watch-webhook-receiver.mjs` is an importable local example. It starts no listener, makes no external requests, and performs no customer action. Supply a private registration secret and an atomic durable inbox implementation. Do not return or log that secret.

The existing HMAC formula is preserved: SHA-256 HMAC of `<x-delta-timestamp>.<exact raw JSON body>`. The additive payload fields `event_id` and `event_created_at` bind event identity and observation-notification creation time inside the signature. `x-delta-event-id` must match the signed body. Retrying an event preserves the event ID, original body and event-created time; each delivery attempt persists and signs a fresh timestamp. The receiver rejects timestamps outside a five-minute window, altered bytes and mismatched identities before writing its inbox.

Implement `inbox.accept(eventId, bodyDigest, payload)` as one atomic durable operation. Return `accepted` only after first insertion commits, `duplicate` when the same ID and body digest already exist, or `conflict` when an ID is reused with another body. Never implement this as an independent read followed by an unprotected write. Run customer effects from the durable inbox using the event ID as the downstream idempotency key. An ACK means accepted into that inbox, not that customer processing or delivery to a person completed.

Sender delivery is at-least-once, with at most five attempts and backoff. A lost acknowledgement or process interruption can produce duplicates, including for existing receivers which previously verified only the original HMAC fields. They must add atomic event deduplication before treating retries as separate actions. Retries do not initiate another Watch check, consume another prepaid slot, or change its prior baseline. Paused, expired and exhausted Watches can still deliver previously queued notifications. No expiration policy is imposed on historical prepaid Watches.

HTTP 2xx acknowledges delivery; redirects are never followed, permanent 4xx failures stop delivery, while 408/429/5xx and uncertain transport outcomes can retry the same event. Exhaustion remains failed/unknown, not delivered. Persist sender event records and original evidence; there is no cleanup or deletion in this change. The sample bounds body reads to 32 KB and ten seconds. Integrators must separately configure request and durable-inbox operation deadlines and secure their inbox storage before deployment. A storage timeout is an unknown outcome; a repeated notification must consult the same durable event identity, never erase the original inbox row.

Each sender notification attempt and outbox promotion has a twenty-second whole-operation deadline, including metadata reads and CAS writes; webhook transport additionally has its existing fifteen-second bound. Metadata reuses Core's actual-stream reader with a Watch-specific 262,144-byte limit; Core order metadata keeps its original 32,000-byte default. Declared size, actual size, truncation and malformed UTF-8 are checked before JSON parsing. The larger Watch envelope accommodates the complete expectations, decision and escaped raw webhook body without truncation; the raw webhook body still has its independent 32,000-byte cap. Registration and final check writes validate serialized record size. Oversized historical records remain preserved and blocked for reconciliation. Notification cursor reads/listing/writes have separate twenty-second bounds. Cancellation prevents later fetches or new writes; an already submitted CAS can still commit after its response times out. Read the durable state on the next attempt rather than asserting cancellation or deleting an unknown outcome.

Existing notifications dispatch independently of the old check scheduler, and a second pass picks up newly committed events after checks finish. CAS prevents duplicate live claims across these passes. The older Watch check inventory and capture/storage path still lacks a whole-operation deadline, so a stalled check can keep the overall scheduled invocation pending; it cannot prevent the independent pass from delivering earlier queued events. Before starting a new check, the shared expected variable cost must be finite and below the originally prepaid unit price. Otherwise the Watch pauses with quota and price preserved. Changing the current retail price alone does not reprice or invalidate a profitable historical obligation. Actual cost accounting for capture failures (D22) is still unresolved; a failed check's legacy zero cost field must not be interpreted as verified zero cost or realized profit.

Receiver `nowSeconds` and `maxSkewSeconds` must be positive safe integers. Invalid numeric configuration fails closed before reading a body or accepting an inbox event; NaN and infinity cannot disable the replay window.
