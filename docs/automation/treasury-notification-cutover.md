The existing Discovery Pulse owns the only scheduled Treasury scan. Its Treasury job runs independently of channel checks. It uses the original checkpoint store and reconciler from candidate `cfbbe40`. The existing standalone `scripts/reconcile-treasury.mjs` and its non-Pulse callers retain their original contract.

## Cutover

1. Provision a dedicated credential for the narrowly authenticated Worker custody API from companion `6887a45`. Secret names are `TREASURY_CUSTODY_WRITER_SECRET` on the Worker and `DELTA_TREASURY_WRITER_SECRET` in the GitHub `delta-treasury` environment. Use a randomly generated value of at least 32 bytes. Only the trusted master branch should be permitted to use this environment. Keep the ordinary operations administrator credential out of GitHub. This writer can read original custody revisions and append validated immutable revisions. The Worker enforces separate authorization on every other operations endpoint. A compromise of the writer would compromise financial observations, so require reviewed changes to this workflow and its protected environment.
2. Deploy the compatible Worker through the release process. Set `OPERATIONS_CLOUD_ENABLED=true`, `TREASURY_CUSTODY_ENABLED=true`, `TREASURY_CUSTODY_ORIGIN_BLOCK=53676533`, `TREASURY_CUSTODY_MINIMUM_VERSION=0`, and `TREASURY_CUSTODY_ALLOW_BOOTSTRAP=true`. Omit the minimum digest; leave Treasury notification projection disabled. Check for an existing authority, including all pages of the revisions prefix. If records exist, recover and reconcile the original authority.
3. Ship this workflow to master. In the protected environment set `DELTA_TREASURY_APPROVED_RELEASE` to the full immutable hash of the reviewed Treasury client and `DELTA_TREASURY_STATE_MODE=remote`. Leave `DELTA_TREASURY_BASELINE_DIGEST` empty until the verified bootstrap revision exists. An ordinary remote scheduled run will fail closed during this brief bootstrap window. Push-triggered runs are read-only rolling diagnostics. Unrelated subsequent master commits do not replace the trusted client used for remote writes.
4. Dispatch the same workflow once on master with `treasury_bootstrap=true`. This explicit bootstrap skips the entire buyer-discovery and marketing job. The scanner rechecks chain ID, finalization and the pinned single-block evidence, including parent header, hash and zero matching logs, then conditionally creates only revision 1. A lost response requires exact readback. Never delete or overwrite an existing revision to repeat this operation. Check the returned digest against the immutable private revision using the schema validator and the original serialization.
5. Pin the same verified digest in Core `TREASURY_CUSTODY_MINIMUM_DIGEST` and GitHub environment `DELTA_TREASURY_BASELINE_DIGEST`. Set Core minimum version to 1 and `TREASURY_CUSTODY_ALLOW_BOOTSTRAP=false`. Scheduled and ordinary manual runs now continue from the original checkpoint, overlap 100 blocks and apply the existing 12-confirmation policy. Keep the notification floor stable. No archive preceding the boundary is imported, and no receipts before this origin can qualify for this notification stream.
6. Once signed delivery and the owner mailbox have been qualified, enable the existing projection, outbox and delivery according to the Core release gate. Verify at least two genuine scheduled runs with consecutive persisted coverage and the 15-minute projection cursor plus the independent timer. If the scanner fails, preserve pending R2 evidence, correct the dependency and resume from the original floor. One diagnostics run or an accepted mail request proves neither an uninterrupted schedule nor receipt of a customer's payment.

Only the aggregate range, checkpoint position, cutover digest and status are published by the Treasury job. Detailed receipts and corrections remain in private custody. HTTP exceptions, payer identities, transfer values and transaction IDs never pass to its logs or artifacts. Customer/funnel details from the existing D1 audit remain in D1. The other pre-existing, public-market discovery activities are separate and receive no Treasury credential.

For secret entry, the official GitHub CLI locally encrypts the value passed on private standard input to `gh secret set DELTA_TREASURY_WRITER_SECRET --env delta-treasury --repo 15998194110/delta-witness`. Use the release operator's secure bridge; do not put the value on the command line, in a repository file or in chat. [GitHub secret storage](https://cli.github.com/manual/gh_secret_set)
