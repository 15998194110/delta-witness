The candidate now prepares canonical repository metadata before running each package's prepack checks, builds a real `.tgz`, records the archive's package identity, source commit, size, SHA256 and SHA512 integrity, and uploads that exact artifact from the verification job. Approved publication jobs download those artifacts and do not rebuild or run lifecycle scripts.

The import-safe `scripts/verified-npm-artifact.mjs` verifies the downloaded archive and its embedded package metadata before registry lookup. A previously published version succeeds only if the registry identifies the same package/version and exact archive SHA512. Missing/different integrity fails closed; an immutable existing `0.7.1` containing different bytes must not be overwritten or silently skipped. A genuinely missing version permits one publication callback, followed by an exact registry integrity readback. Lost or incompatible readback fails the run and never triggers another publication callback. Registry HTTP/body duration and size are bounded; denial, timeout or malformed evidence is not interpreted as absence.

Independent review found that the archive could change during the asynchronous registry lookup. The helper now re-reads and hashes the original artifact and manifest immediately before publication. This qualifies the trusted isolated CI artifact-directory model; it is not an atomic filesystem guarantee against arbitrary concurrent hostile writers. Downloaded workflow artifacts and provider registry integrity are the stated authorities, not an independent signed provenance attestation.
