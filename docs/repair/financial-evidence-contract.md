# P0-3 financial evidence import and original-order join

This increment starts at `149c302`. It adds evidence custody/read-only ingestion and composes the existing `accounting.ts` readers/derivation. It does not replace original orders, settlement journals, fulfillment/artifacts or the canonical Treasury checkpoint. It performs no payment, refund, repricing, production migration, scheduler activation or deletion.

## Authorities and source limitations

| Fact | Source and implemented handling | Required qualification |
|---|---|---|
| Authorization / confirmed settlement / original delivery | Existing `readCoreAccountingEvidence`; original order and proof validators | Never inferred from telemetry, imported audit flags or invoice data |
| Treasury received | Existing `deriveOrderAccounting` and canonical checkpoint validator | Unique tx + log index, payer, amount and original-order match; covered blocks retain their original range |
| Invoice available | Connected Gmail metadata or an explicitly imported notice | Notification only. Even `$0.00 due` does not establish invoice subtotal, DELTA allocation, cost coverage or zero expenses |
| Account billing history | New fixed `GET https://api.cloudflare.com/client/v4/accounts/{account_id}/billing/history` adapter | Billing Read authorization, bounded pages/body/deadline; results are account-level events, not DELTA service lines or per-order expenses |
| Buyer purpose / refunds / expense allocation | Digest-bound audit-support references plus a separately reviewed internal source verifier | A source label or caller JSON cannot verify itself. Missing verifier/source/refund coverage/actual cost categories remains unknown |
| USD expense versus USDC revenue | Original currency retained | No automatic USD=USDC conversion. A real cost verifier must check executed conversion/FX, credits/tax/rounding and documented allocation before returning USDC raw costs |

Official interface checked on 2026-11-04: [Cloudflare Billing History](https://developers.cloudflare.com/api/resources/billing/subresources/history/methods/list/) accepts Billing Read. Its documented records contain invoice references, currency, amount and amount remaining; they do not contain a DELTA order-allocation contract. The adapter does not access payment-method, charge, pay-invoice, key-management or setup endpoints.

[Browser Run pricing](https://developers.cloudflare.com/browser-run/pricing/) describes `X-Browser-Ms-Used` as a usage measurement suitable for estimation and monthly billing rounding. [R2 pricing](https://developers.cloudflare.com/r2/pricing/) also includes monthly allowances and billing-unit rounding. Those documents do not prove this account's actual invoice or individual order's allocation. Original proof cost models remain models.

## Durable contract

`FinancialSource` is a strict allowlist: invoice notice, sanitized billing-history page, order-audit assertion, or digest-only audit-support reference. It excludes full email/MIME, recipients, descriptions, hosted/magic invoice URLs, account credentials, payment details and arbitrary provider text. Source observation time and source reference are distinct from the economic period; the account listing cannot be promoted to complete order coverage.

`FinancialSourceEnvelope` binds SHA-256 of canonical normalized source bytes. `retainFinancialSource` conditionally creates only `operations/financial-evidence/sources/<digest>.json`, then reads the same digest back. Unknown writes receive no second identity or blind resend. Repeated identical sources preserve original bytes; different observations append different content identities. This is an evidence journal, not a balance ledger. Hash integrity does not authenticate the claimed issuer.

The offline CLI is `node scripts/import-financial-evidence.mjs --input <reviewed-json> --store <private-directory> --output <new-report.json>`. It reads a bounded explicit JSON file, uses the same module, writes source files and output with create-only semantics, and makes no provider call or credential lookup. Caller-supplied `authenticated_*`/connected labels are downgraded to `local_import`; `synthetic_fixture` remains explicit. It cannot make an invoice/provider verification claim. It rejects archive-key traversal and symbolic archive objects. Windows access-control inheritance still requires qualification before real customer/finance data is imported; POSIX modes alone are not a Windows ACL guarantee.

## Join contract and trust boundary

`readFinancialAccounting(env, {as_of?, order_ids, source_hashes, treasury_checkpoint}, optionalVerifier)` reads at most five scoped original Capture/Preflight orders and fifty bounded source records, with an overall sixty-second read/cancellation fence. Source lookup has a ten-second phase budget and two-second individual limit; each original-order read has seven seconds. An unavailable/corrupt expense source is explicitly missing and cannot erase separately readable order facts. Original readers and per-order snapshots retain their own bounds. Missing/future source dependencies and conflicting per-order audits fail closed or remain explicitly missing.

When `as_of` is omitted, the view records its cut after the reads so a fresh observation is not accidentally placed after its own request-start timestamp. An explicitly supplied historical cut is preserved: current/future observations cannot rewrite an earlier financial snapshot.

The module calls the original accounting kernel. No second receipt algorithm, rolling Treasury scan, payment counter, quote/402 revenue counter or mutable financial balance is created. Unpaid intents, authorized, settled, received, delivered, recognized, refunds, actual variable costs and margin remain distinct. Received-but-unfulfilled liabilities retain the original accounting responsibility fields. Selected-order coverage and `all_time_verified:false` are explicit.

The optional verifier is an **internal injected adapter**, not a request JSON flag. It must independently inspect the exact source digest, original invoice/credit/expense documents, cost allocation and non-duplicated expense pool, FX evidence, complete refund ledger and customer-purpose evidence. Approval is bound to the exact audit digest, a separately computed support-graph digest, and verification time. Each non-hash alias must resolve to exactly one selected source before document-type/order filtering. Conflicting or duplicate aliases remain unknown; canonical hash references select only the exact immutable source, never a hash-shaped alias. Replacing even a uniquely aliased document changes the graph digest, so an old approval cannot authorize its new support edge. Matching order-bound support references of the correct document type are required; notices/history cannot certify expenses or refunds even if a verifier is mistaken. Missing any of the seven actual variable-cost categories leaves actual cost and margin null; support/acquisition remain separate operating costs.

There is intentionally **no production actual-invoice verifier yet**. The Cloudflare history endpoint and email notices cannot supply all of its missing evidence. The default join therefore does not recognize imported audit assertions as independently verified customer revenue or actual profit. Synthetic verifier tests demonstrate the composition contract and are labeled `synthetic_not_customer_activity`.
